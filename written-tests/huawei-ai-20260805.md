## 01 · 基站空间重叠区域识别 {#problem-01}

### 题目描述

无线网络运维需要根据基站的密集程度识别信号重叠区域。给定 $N$ 个平面基站 $P_i(x_i,y_i)$、距离门限 $\varepsilon$ 和邻域数量门限 $MinPts$。

若两个基站满足

$$
d(P_i,P_j)=|x_i-x_j|+|y_i-y_j|\le \varepsilon,
$$

则称 $P_j$ 位于 $P_i$ 的空间邻域内。一个基站的邻域**包含它自身**。

按照下面的规则为每个基站分类：

- **核心点（Core）**：邻域内的基站总数不少于 $MinPts$；
- **边界点（Border）**：自身不是核心点，但邻域内至少存在一个核心点；
- **噪声点（Noise）**：既不是核心点，也不是边界点。

请按输入顺序输出每个基站的类别编号：`0` 表示 Core，`1` 表示 Border，`2` 表示 Noise。

### 输入格式

第一行包含三个整数 $N,\varepsilon,MinPts$：

- $1\le N\le 2000$；
- $0\le \varepsilon\le 10000$；
- $1\le MinPts\le N$。

接下来 $N$ 行，每行包含两个整数 $x_i,y_i$，表示第 $i$ 个基站的坐标，并满足：

$$
-10000\le x_i,y_i\le 10000.
$$

### 输出格式

输出 $N$ 行，第 $i$ 行输出第 $i$ 个基站的类别编号。

### 样例 1

**输入**

```text
5 1 2
0 0
1 0
-1 0
0 1
0 -1
```

**输出**

```text
0
0
0
0
0
```

每个外围点的邻域都包含自身和原点，邻域规模至少为 $2$，因此五个点都是核心点。

### 样例 2

**输入**

```text
5 1 3
0 0
1 0
0 1
5 5
9 9
```

**输出**

```text
0
1
1
2
2
```

原点的邻域规模为 $3$，所以它是核心点。$(1,0)$ 与 $(0,1)$ 不是核心点，但都与原点相邻，所以是边界点；其余两个点是噪声点。

### 解题思路

#### 1. 先统计所有邻域大小

每个点都与自身相邻，因此令 `neighbor_count[i] = 1`。随后只枚举一次无序点对 $(i,j)$，其中 $i<j$：

- 若两个点的曼哈顿距离不超过 $\varepsilon$，同时增加两端的邻域计数；
- 否则不做处理。

这样既不会漏掉任意一对不同基站，也不会把同一对重复统计两次。

#### 2. 一次性确定核心点集合

当且仅当 `neighbor_count[i] >= min_pts` 时，第 $i$ 个点是核心点。

边界点依赖于**最终的核心点集合**。因此不能在统计邻域数量的过程中顺便判断边界点，否则一个尚未统计完邻域的点可能被错误地当成非核心点。

#### 3. 判断 Border 和 Noise

对于每个非核心点，扫描所有核心点：

- 只要存在一个核心点与它的距离不超过 $\varepsilon$，它就是边界点；
- 若扫描结束仍未找到相邻核心点，它就是噪声点。

### 正确性证明

**引理 1：点对枚举结束后，`neighbor_count[i]` 等于第 $i$ 个基站真实的邻域大小。**

初始化时已经计入基站自身。任意两个不同基站恰好对应一个无序点对 $(i,j)$，程序只在它们的曼哈顿距离满足门限时同时增加两端计数。因此所有且仅有位于邻域内的基站都会被计入，引理成立。

**引理 2：`is_core[i]` 能正确判断第 $i$ 个基站是否为核心点。**

由引理 1，`neighbor_count[i]` 是真实邻域大小。程序按照题目定义检查它是否不少于 $MinPts$，因此核心点判断正确。

**引理 3：每个非核心点会被正确分类为边界点或噪声点。**

程序检查该点邻域内是否存在由引理 2 正确确定的核心点。若存在就输出 `1`，与边界点定义一致；若不存在就输出 `2`，此时它既不是核心点，也不与任何核心点相邻，与噪声点定义一致。

由以上三个引理，程序对所有基站给出的类别都正确。

### Python ACM 实现

```python
import sys


def solve() -> None:
    input = sys.stdin.buffer.readline
    n, eps, min_pts = map(int, input().split())
    points = [tuple(map(int, input().split())) for _ in range(n)]

    # 邻域包含基站自身，所以计数从 1 开始。
    neighbor_count = [1] * n

    # 每个无序点对只检查一次；若相邻，同时更新两端的邻域大小。
    for i in range(n):
        xi, yi = points[i]
        for j in range(i + 1, n):
            xj, yj = points[j]
            if abs(xi - xj) + abs(yi - yj) <= eps:
                neighbor_count[i] += 1
                neighbor_count[j] += 1

    # 必须先完整确定核心点集合，再判断边界点。
    is_core = [count >= min_pts for count in neighbor_count]
    core_indices = [i for i, core in enumerate(is_core) if core]

    answer = [2] * n
    for i in range(n):
        if is_core[i]:
            answer[i] = 0
            continue

        xi, yi = points[i]
        for j in core_indices:
            xj, yj = points[j]
            if abs(xi - xj) + abs(yi - yj) <= eps:
                answer[i] = 1
                break

    sys.stdout.write("\n".join(map(str, answer)))


if __name__ == "__main__":
    solve()
```

### 复杂度分析

- **时间复杂度**：$O(N^2)$。邻域计数需要枚举点对；非核心点判断最坏也需要扫描全部核心点。
- **空间复杂度**：$O(N)$，用于保存坐标、邻域计数、核心点标记和答案。

### 易错点

1. 邻域包含自身，计数初值不能写成 `0`；
2. 题目使用曼哈顿距离，不是欧氏距离，不需要开平方；
3. 距离恰好等于 $\varepsilon$ 时也属于邻域；
4. 必须先确定所有 Core，再判断 Border；
5. 即使两个基站坐标相同，它们仍是两个不同的输入点，彼此都要计入邻域。

## 02 · 多 Agent 协作任务调度 {#problem-02}

### 题目描述

一个多 Agent 系统包含 $N$ 个 Agent。每调用一次第 $i$ 个 Agent，任务进度增加 $p_i$ 个百分点，并产生代价 $c_i$。

每个 Agent 可以调用任意多次，但**不能连续两次调用同一个 Agent**。

当累计进度达到或超过 $100$ 时任务完成，最终进度允许超过 $100$。请计算完成任务所需的最小总代价；若无法完成，输出 `-1`。

### 输入格式

第一行输入一个整数 $N$，满足：

$$
1\le N\le 10^5.
$$

接下来 $N$ 行，每行包含两个整数 $p_i,c_i$：

- $1\le p_i\le 100$；
- $1\le c_i\le 10^4$。

### 输出格式

输出一个整数，表示完成任务所需的最小总代价；若无解，输出 `-1`。

### 样例 1

**输入**

```text
1
60 5
```

**输出**

```text
-1
```

只有一个 Agent。调用一次后进度为 $60$，再次调用会违反“相邻调用不同 Agent”的限制，因此无法完成任务。

### 样例 2

**输入**

```text
3
30 1
40 2
100 50
```

**输出**

```text
4
```

依次调用 Agent 1、Agent 2、Agent 1，进度为 $30+40+30=100$，总代价为 $1+2+1=4$。

### 从朴素 DP 开始建模

由于 $p_i\ge 1$，每次调用都会严格增加进度。只需保存未完成状态 `0...99`；一旦新进度达到 $100$，就直接更新最终答案。

最直接的状态是：

$$
dp[s][i]=\text{累计进度恰为 }s\text{，且最后调用 Agent }i\text{ 时的最小代价}.
$$

如果下一次调用 Agent $k$，上一个 Agent 不能是 $k$，因此转移需要：

$$
\min_{i\ne k}dp[s][i]+c_k.
$$

若对每个进度枚举上一位和下一位 Agent，复杂度为 $O(100N^2)$，无法处理 $N=10^5$。

### 优化：每层只保留两个关键最值

固定进度 $s$ 和下一位 Agent $k$。求“排除 $k$ 后的最小代价”时，只会遇到两种情况：

1. 当前层全局最优状态的末尾不是 $k$，直接使用全局最小值；
2. 当前层全局最优状态的末尾正好是 $k$，必须改用一个由其他 Agent 结尾的最小值。

因此对每个进度层只维护：

- `best[s]`：该层所有状态的最小代价；
- `best_last[s]`：取得 `best[s]` 的末尾 Agent；
- `second[s]`：末尾 Agent 与 `best_last[s]` 不同的状态中的最小代价。

调用 Agent $k$ 前的合法最小代价为：

$$
base=
\begin{cases}
second[s], & k=best\_last[s],\\
best[s], & k\ne best\_last[s].
\end{cases}
$$

得到 `new_cost = base + cost[k]` 后：

- 若 `s + progress[k] >= 100`，用 `new_cost` 更新答案；
- 否则把 `(new_cost, k)` 合并到目标进度层的最小值体系中。

进度为 `0` 时还没有调用过任何 Agent，因此设置 `best[0] = 0`、`best_last[0] = -1`。所有真实 Agent 编号都不等于 `-1`，第一次调用自然不受相邻限制。

### 为什么可以按进度从小到大处理

每个 $p_i$ 都至少为 $1$，所以任意转移都从进度 $s$ 指向更大的进度 $s+p_i$。状态图是一张按进度递增的有向无环图。处理到进度 $s$ 时，所有可能到达它的更小进度都已经完成转移，因此可以直接从 `0` 到 `99` 扫描，不需要反复松弛。

### 正确性证明

**引理 1：对于固定进度 $s$ 和待调用 Agent $k$，程序选择的 `base` 等于所有末尾不为 $k$ 的状态中的最小代价。**

若 `best_last[s] != k`，全局最小状态合法，`best[s]` 就是答案。若 `best_last[s] == k`，全局最小状态因连续调用同一 Agent 而不合法；按照 `second[s]` 的定义，它正是末尾为其他 Agent 的状态中的最小代价。因此引理成立。

**引理 2：每次合并新状态后，目标层的 `best`、`best_last` 和 `second` 仍保持定义。**

若新状态优于当前 `best`，它成为新的全局最小值；当末尾 Agent 改变时，原最小值自然成为一个合法的异 Agent 次小候选。若新状态没有优于 `best`，只有在它的末尾 Agent 不同且代价更小时才更新 `second`。两种分支都保留了全局最小值和排除其末尾 Agent 后的最小值，所以不变量成立。

**引理 3：处理完进度 $s$ 后，所有从进度 $s$ 出发的合法下一次调用都已按最小代价转移。**

程序枚举每个 Agent 作为下一次调用，并由引理 1 取得符合相邻限制的最小前驱代价，因此不会漏掉任何合法末次 Agent 组合，也不会使用非法的连续重复调用。

状态只向更大进度转移。结合引理 2 和引理 3，按进度归纳可知所有未完成状态都保存了所需的最优信息；所有达到或超过 $100$ 的合法方案都会更新答案，答案取其中最小值。因此程序输出最小总代价；若答案从未被更新，则确实不存在合法完成方案，输出 `-1` 正确。

### Python ACM 实现

```python
import sys


def solve() -> None:
    input = sys.stdin.buffer.readline
    n = int(input())

    progress = [0] * n
    costs = [0] * n
    for i in range(n):
        progress[i], costs[i] = map(int, input().split())

    inf = 10**30

    # 只保存尚未完成的 0...99 进度。
    best = [inf] * 100
    second = [inf] * 100
    best_last = [-1] * 100

    # 虚拟起点没有“上一个 Agent”，第一次可以选择任意 Agent。
    best[0] = 0
    answer = inf

    for current in range(100):
        if best[current] == inf:
            continue

        for agent in range(n):
            # 若最优状态以当前 Agent 结尾，就必须改用异 Agent 次小值。
            if best_last[current] == agent:
                base = second[current]
            else:
                base = best[current]

            if base == inf:
                continue

            new_cost = base + costs[agent]
            next_progress = current + progress[agent]

            if next_progress >= 100:
                answer = min(answer, new_cost)
                continue

            # 把“代价 new_cost、末尾 agent”合并到目标进度层。
            if new_cost < best[next_progress]:
                if best_last[next_progress] == agent:
                    # 最优状态仍由同一个 Agent 结尾，异 Agent 次小值不变。
                    best[next_progress] = new_cost
                else:
                    # 新状态成为最优；原最优来自另一个 Agent，可转为次小值。
                    second[next_progress] = best[next_progress]
                    best[next_progress] = new_cost
                    best_last[next_progress] = agent
            elif (
                best_last[next_progress] != agent
                and new_cost < second[next_progress]
            ):
                second[next_progress] = new_cost

    print(-1 if answer == inf else answer)


if __name__ == "__main__":
    solve()
```

### 复杂度分析

- **时间复杂度**：$O(100N)$。最多处理 100 个未完成进度层，每层扫描全部 Agent。
- **空间复杂度**：$O(N)$，用于保存所有 Agent 的进度增量与代价；DP 数组长度固定为 100。

### 易错点

1. 普通完全背包状态没有记录上一位 Agent，无法检查相邻不同限制；
2. `second[s]` 不是简单的第二个数值，而是末尾 Agent 与 `best_last[s]` 不同的最小代价；
3. 同一 Agent 刷新 `best` 时，不能用旧 `best` 覆盖 `second`；
4. 新进度达到或超过 `100` 后应直接更新答案，不再保存为 DP 状态；
5. 只有一个 Agent 且其单次进度小于 `100` 时无解，上述 DP 会自然输出 `-1`；
6. 进度 `0` 是没有末尾 Agent 的虚拟起点，不能把它错误地视为某个真实 Agent。

## 本场复盘

- 第一题难点不在数据结构，而在忠实还原 DBSCAN 的三类点定义。两阶段处理可以避免分类依赖顺序。
- 第二题的关键是先保留“上一个 Agent”这一必要信息，再观察一次转移只需要排除一个编号，从而用两个最值压缩状态。
- 面试讲解时应先写出朴素状态和超时原因，再给出最值优化；直接抛出 `best/second` 数组通常不容易让听者理解其来源。
