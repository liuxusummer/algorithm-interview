# 狼人杀情报甄别 API 服务

<div class="ai-trend-callout">
  <strong>训练重点</strong>
  <p>公开卡片强调观察式题面。候选人需要把示例转成明确、可版本化的规则，再实现单条甄别、批量回放和历史查询。AI 可以帮助枚举假设，但不能凭游戏常识发明规则。</p>
</div>

## 资料边界

公开题单卡片给出的功能是单条甄别、批量回放和历史查询，涉及 API、观察式题面与在线判定。角色、语句结构和真假规则未公开。本页训练规格推断、服务边界与验证流程，不声称给出原题规则。

来源：[牛客 AI Coding 公开题单](https://aicoding.nowcoder.com/questionlist)。

## 训练题目

给定若干“局面＋情报＋判定”示例和 HTTP 骨架，推断情报甄别规则。服务对单条请求返回结论、命中规则和解释；批量接口按既定语义执行；历史接口能够按请求 ID 查询当时使用的规则版本与结果。

## 先把游戏常识关在门外

事实表只记录示例中出现的角色、关系、事件和输出。AI 若说“狼人通常会撒谎”并据此补规则，应立即拒绝，因为题目可能使用完全不同的抽象逻辑。

::: tip Prompt 01｜事实与假设分栏
```text
下面是公开示例的结构化记录。
请分成“直接事实、候选规则、需要区分的竞争规则、未知项”四栏。
禁止使用狼人杀常识补充题面，也不要生成判定代码。
```
:::

## 用最小实验区分候选规则

若两条规则都能解释现有样例，构造只改变一个变量的输入。优先验证规则优先级、冲突处理、顺序敏感和缺失字段。不能访问新的裁判结果时，应保留不确定性，不把猜测写进服务。

::: tip Prompt 02｜主动区分
```text
对每组竞争规则设计最小区分样例。
说明不同规则各自预测什么、观察哪个字段即可裁决，以及若无法调用裁判应该如何在文档中保留 UNKNOWN。
```
:::

## 判定结果必须可解释且可版本化

返回结论之外，还要记录命中规则 ID、输入规范化摘要和规则版本。规则升级后查询旧历史，仍应解释当时为何得到该结果，而不是使用新规则重新计算覆盖旧记录。

::: tip Prompt 03｜结果契约
```text
为单条甄别响应定义最小可解释字段。
区分输入错误、无法判定、合法结论和规则冲突；说明规则版本、解释和请求 ID 的作用。
不要在解释中泄露内部堆栈或未公开数据。
```
:::

## 批量回放要固定顺序与失败语义

如果每条情报独立，可逐项返回；若前一条会改变局面，批次顺序就是业务语义。先确认批量是否共享状态、遇错继续还是停止，以及重放历史是读取旧结果还是按指定版本重新计算。

::: tip Prompt 04｜批量状态时间线
```text
请分别推演“每条独立”和“共享局面状态”两种批量模型。
对第三条输入非法的五条批次，列执行顺序、最终状态、逐项结果和重试行为。
指出必须从题面确认的选择，不让实现自行决定。
```
:::

## 历史查询是审计，不只是保存请求体

历史记录至少包含规范化输入摘要、结果、规则版本、时间和请求 ID。若包含玩家敏感信息，应最小化存储并限制查询。记录应在判定提交后写入一致结果，失败请求是否保留也需明确。

::: tip Prompt 05｜审计与隐私
```text
审查历史记录字段和访问边界。
列出调试所需、业务解释所需和不应长期保存的字段；再构造重复请求、规则升级、删除请求和越权查询四种轨迹。
```
:::

## 验收证据

- 每条规则都能追溯到观察或区分实验。
- 相同输入和规则版本得到相同结果。
- 冲突与无法判定不会被伪装成确定结论。
- 批量顺序、失败和重试语义一致。
- 旧历史始终引用当时规则版本。

::: tip Prompt 06｜幻觉审查
```text
请扫描当前规格和解释文案，找出所有没有示例证据支持的规则、游戏常识和因果说法。
把它们分为“必须删除、需要确认、可以作为训练假设但必须标注”三类。
最后给出一组回归轨迹验证规则版本与历史一致性。
```
:::

## 面试复述

按“观察—竞争假设—区分实验—版本化规则—批量语义—历史审计”复述。最关键的是承认未公开规则未知，并展示自己如何阻止 AI 用游戏常识把未知包装成确定答案。
