# ToB 企业活动策划

<div class="ai-trend-callout">
  <strong>训练重点</strong>
  <p>AI 能快速写出完整活动方案，但最容易产出空泛的“主题演讲＋圆桌交流”。候选人要先确定商业目标、受众与资源约束，再让每个环节对应一个可验证结果。</p>
</div>

## 资料边界

公开卡片要求策划一场企业数字化管理系统行业沙龙，考查策划思维、细节洞察、问题解决与落地能力。品牌、预算、城市和人数未公开，本页采用一组训练假设展示作答方法，不声称复原完整原题。

来源：[牛客 AI Coding 公开题单](https://aicoding.nowcoder.com/questionlist)。

## 训练题目

在 30 分钟内提交一页主方案和一页执行清单。活动面向中型企业数字化负责人，目标是在不夸大产品能力的前提下形成有效商机并沉淀行业内容。所有预算、人数和渠道假设必须显式标注。

## 先把“办活动”拆成目标树

业务目标、用户价值和活动产物要相互对应。例如业务目标是获得高质量后续沟通，用户价值是带走可落地的方法，产物是诊断表和会后资料。若只写曝光量，无法解释为什么要办行业沙龙而不是投放广告。

::: tip Prompt 01｜目标澄清
```text
你是我的反方策划顾问。请把“办一场数字化行业沙龙”拆成业务目标、受众价值和可交付产物。
所有人数、预算、转化率假设标记 ASSUMPTION；信息不足时列出需要向出题人确认的问题。
不要先生成议程或宣传文案。
```
:::

## 用受众旅程设计内容

从报名、审核、会前触达、到场、参与、会后跟进逐段设计。每段只解决一个主要问题：为什么值得来、是否适合、如何参与、能带走什么、下一步是什么。议程要围绕真实痛点，而不是按公司领导职级排顺序。

::: tip Prompt 02｜受众旅程
```text
请为目标受众画六阶段旅程。
每阶段列用户疑虑、我们的动作、所需素材、成功信号和可能流失点。
禁止使用“加强互动”“提升体验”这类不可验证表述。
```
:::

## 议程必须服务于目标

训练版可采用案例拆解、同行圆桌和行动工作坊。每个环节写输入、主持动作、输出和时间盒。产品演示只能回答前面确认的痛点，不能把整场活动变成长功能宣讲。

::: tip Prompt 03｜议程压力测试
```text
这是目标树和初版议程。
请逐项检查每个环节支持哪个目标、产出什么、超时会挤压谁。
删除无法对应目标的环节，并设计一个避免圆桌泛聊的主持问题框架。
```
:::

## 落地靠 RACI 和运行手册

明确负责人、批准人、协作者和知会人；会前按倒计时列场地、嘉宾、物料、报名数据和应急检查。现场运行手册要精确到时间、岗位、提示语、设备和失败替代方案。

::: tip Prompt 04｜执行清单
```text
请把方案转成 T-14、T-7、T-1、T-0、T+1 的执行清单。
每项写负责人角色、完成证据、依赖和失败替代方案。
不虚构具体同事姓名，也不默认场地方会解决设备问题。
```
:::

## 预案要按影响与概率排序

重点处理嘉宾缺席、到场不足、设备故障、内容合规、超时、突发投诉和敏感客户信息。预案必须能在现场执行，例如准备替补案例和离线资料，而不是写“及时协调处理”。

::: tip Prompt 05｜桌面演练
```text
选择影响最大的五个风险，为每个风险写触发信号、现场负责人、前五分钟动作、对外口径和恢复条件。
请扮演活动当天的故障注入者，检查预案是否真的可执行。
```
:::

## 指标分领先与滞后

报名审核通过率、关键嘉宾确认率属于会前领先指标；到场率、有效问答数、会后预约和内容复用属于结果指标。避免把交换名片数直接当高质量商机。

这一阶段还要做一次 AI 输出审查：删掉没有负责人、完成证据或数据来源的漂亮口号，保留能在活动前后实际核验的动作与指标。

::: tip Prompt 06｜复盘指标
```text
请为目标树设计一组最小指标，区分领先指标、现场指标和会后结果。
每个指标写数据来源、统计窗口和可能被误读的地方。
最后给出一次复盘会议必须回答的五个问题。
```
:::

## 面试复述

按“目标—受众—议程—执行—风险—指标”复述。说明 AI 初稿中哪一段看似完整却无法落地，以及你如何用负责人、完成证据和失败替代方案把它改造成运行手册。
