# 通讯录系统 API 服务

<div class="ai-trend-callout">
  <strong>训练重点</strong>
  <p>完整通讯录同时维护联系人主记录、分类、首字母分组和号码前缀统计。新增容易，更新与删除才真正考验设计：所有派生索引必须一起撤销旧值、写入新值。</p>
</div>

## 资料边界

公开卡片要求联系人增删改查、分类查询、首字母分组与号码前缀统计，涉及 API、CRUD、索引维护和状态一致性。完整数据模型及排序规则未公开，本页据此重建过程型训练，不声称复原完整原题。

来源：[牛客 AI Coding 公开题单](https://aicoding.nowcoder.com/questionlist)。

## 训练题目

实现联系人资源及分类、分组、前缀查询接口。联系人拥有稳定 ID，姓名、号码和分类可更新。读取接口支持稳定排序和分页；写入失败不得让主记录与任何派生索引不一致。

## 数据模型先于路由数量

确认联系人和号码是一对一还是一对多，分类是枚举、标签还是独立资源，姓名首字母如何计算，以及号码是否唯一。API 路由应表达领域动作，不能每个查询方式都复制一套存储逻辑。

::: tip Prompt 01｜领域问题清单
```text
请把联系人、号码、分类和首字母分组之间的基数关系列成确认表。
对唯一性、空值、排序、分页、Unicode 姓名和删除语义逐项说明会影响哪些接口。
未知内容标记 UNKNOWN，不直接设计数据库表。
```
:::

## 派生索引不是第二份真相

分类、首字母和号码前缀都是主记录的投影。设计统一的“从联系人计算索引项”和“应用索引差异”过程，使创建、更新和删除复用同一规则。禁止在三个路由中手写三份索引维护。

::: tip Prompt 02｜索引依赖图
```text
根据联系人字段，画出分类索引、首字母索引和前缀索引的依赖图。
对每个可更新字段说明旧索引如何撤销、新索引如何建立，以及哪些索引不受影响。
不生成实现。
```
:::

## 更新要以旧快照和新快照求差

先读取旧对象，验证补丁得到新对象，计算两者的索引差异，最后原子提交。若客户端带版本号，可拒绝基于旧版本的覆盖更新。部分字段更新还要区分“未提供”和“显式清空”。

::: tip Prompt 03｜更新事务
```text
构造一次同时修改姓名、号码和分类的更新。
请按读取旧版本、合并补丁、验证、计算索引差异、提交、返回的顺序列状态。
加入并发版本冲突和中途失败，证明不会留下半更新索引。
```
:::

## 查询必须稳定且可分页

分类与首字母分组结果要定义主排序和唯一决胜键，否则翻页时会重复或漏项。前缀查询返回计数还是联系人列表也要明确；列表模式还涉及去重和权限字段。

::: tip Prompt 04｜查询契约
```text
为列表、分类、首字母分组和号码前缀查询定义过滤、排序、分页和返回字段。
特别检查相同姓名、更新发生在翻页之间、空结果和非法游标。
不要用数据库默认顺序作为契约。
```
:::

## 删除要验证所有反向引用

删除联系人后，分类桶、首字母桶和所有号码前缀计数都必须回退。重复删除应返回同一语义或明确未找到，不能继续递减计数。保留软删除时，查询和唯一性规则也要相应定义。

::: tip Prompt 05｜删除对账
```text
为一个拥有多个号码和分类的联系人设计删除前后对账表。
列主存储、每类索引、计数和查询结果；再推演重复删除与事务失败。
只给期望状态，不写删除代码。
```
:::

## 验收策略

- 从主存储重建全部索引，与增量维护结果一致。
- 创建、跨组更新、删除后查询结果立刻一致。
- 重复请求不会重复创建或把计数减为负数。
- 稳定排序保证分页边界可解释。
- 非法补丁和版本冲突不改变任何状态。

::: tip Prompt 06｜最终一致性审查
```text
请把当前服务当作“一个主记录加三个派生索引”审查。
找出每个写接口可能遗漏的撤销动作、并发覆盖、分页不稳定和规范化漂移。
为每项给一个端到端 API 轨迹及重建索引的对账方法。
```
:::

## 面试复述

把重点放在旧快照—新快照—索引差异，而不是 CRUD 路由数量。说明如何让 AI 输出依赖图和对账轨迹，再用重建索引验证增量维护正确。
