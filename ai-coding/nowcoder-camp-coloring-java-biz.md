# 阵营涂色 Java Biz 实现

<div class="ai-trend-callout">

  <p>原环境强调 Java，但本站不展示成品实现。训练重点是控制层不能改时，如何从 DTO、调用点和测试还原业务契约，限制 AI 只修改 Biz 层，并证明没有靠改接口躲过问题。</p>

## 资料边界

公开卡片要求在控制层锁定的前提下，实现阵营投放、移动与吞并的核心业务逻辑，涉及状态机、并查集与复杂度优化。完整 Java 骨架和接口没有公开，本页基于该约束重建过程型训练，不声称复原原仓库。

来源：[牛客 AI Coding 公开题单](https://aicoding.nowcoder.com/questionlist)。

## 训练题目

仓库中的 Controller、DTO 和公开测试不可修改，Biz 层留有缺失逻辑。候选人要通过入口调用、对象约束和失败测试理解契约，完成核心规则并补充不越界的测试说明。所有算法思考仍可用伪状态和表格表达，不提供 Java 成品代码。

## 先做“锁定面”清单

记录不可修改文件、公开方法签名、序列化字段、异常映射和测试启动命令。任何 AI 建议若要求改 Controller、DTO 字段或测试预期，都先拒绝。还要检查哪些类虽然可改，却被反射或框架约定隐式依赖。

::: tip Prompt 01｜只读契约考古
```text
根据 Controller、DTO、Biz 接口、调用位置和失败测试生成契约事实表。
每条结论引用具体符号；区分显式约束、框架约定和推断。
暂时不要改代码，不要建议修改锁定层或测试。
```
:::

## 把领域规则集中在 Biz 层

控制器只解析输入和映射响应，Biz 层负责验证前态、计算后态和返回领域结果。避免用异常字符串承载正常分支，也不要让 DTO 变成可随意修改的内部状态对象。

::: tip Prompt 02｜职责边界审查
```text
请为每个业务步骤标注应属于 Controller、Biz、领域对象还是存储层。
发现当前骨架职责混乱时，给最小可行适配方案，但不得改变公开签名和响应结构。
```
:::

## 先在快照上计算，再提交

复杂移动和吞并可能修改多个对象。先根据不可变快照验证全部条件，生成变化集，最后提交。若中途抛错，原状态必须保持。AI 常见错误是在遍历集合时原地修改，使后续判断读取到半成品状态。

::: tip Prompt 03｜变化集设计
```text
把一次移动拆成“读取快照、验证、计算变化集、检查不变量、提交”五阶段。
列出每阶段允许读写的对象，以及失败注入后原状态应如何证明未变。
不要生成 Java 方法实现。
```
:::

## 数据结构必须匹配更新模式

普通并查集适合只合并不拆分。如果移动会删除格子或拆开连通分量，应考虑局部重建、按命令重新搜索或题目提供的特殊单调性。120 分钟内选择可解释且满足规模的方案，比追求最复杂结构更可靠。

::: tip Prompt 04｜复杂度与更新模式
```text
根据命令类型和规模，列出每种操作是否增加边、删除边或改变归属。
比较全量重算、局部搜索、并查集与离线处理的适用前提和复杂度。
缺少规模时不宣称某方案一定通过。
```
:::

## 测试不能绕过锁定接口

从公开 Controller 入口验证主路径，再对 Biz 层写小范围领域测试。必须覆盖非法前态、边界坐标、重复命令、吞并链和失败无副作用。不要通过直接构造不可能出现的内部对象获得虚假覆盖率。

::: tip Prompt 05｜分层测试
```text
请将测试分为公开契约、Biz 规则和不变量三层。
每层给最小样例、观察点和它不能证明的内容。
审查测试是否修改锁定文件、依赖实现细节或绕过真实入口。
```
:::

## 交付前 diff 审查

检查是否意外格式化大量 Java 文件、修改公开签名、放宽异常、硬编码样例或引入新依赖。让 AI 解释每个改动与哪条失败证据相关；无法关联的改动应撤回。

::: tip Prompt 06｜锁定边界复盘
```text
这是锁定面清单、根因证据、修改摘要和测试结果。
请逐项判断是否越界、是否隐藏部分提交、是否依赖未公开行为，以及哪些改动无法由需求证明。
只做审查，不提出风格重构。
```
:::

## 面试复述

强调“控制层锁定”如何改变解题策略：先读调用契约、再设计领域变化集、最后用公开入口验证。说明一次 AI 建议改 DTO 或测试的越界行为，以及你如何把修改收回 Biz 层。
