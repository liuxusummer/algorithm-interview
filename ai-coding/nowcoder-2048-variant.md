# 2048 变体规则推断

<div class="ai-trend-callout">
  <strong>训练重点</strong>
  <p>题目故意不把合并规则全部写成文字，而是要求从动画推断。AI 可以提出假设，但候选人必须维护“观察—假设—反例”账本，不能让熟悉的标准 2048 规则覆盖真实证据。</p>
</div>

## 资料边界

公开卡片说明这是一个 2048 变体，需要从动画 GIF 推断不同于标准版的合并规则并实现五个核心函数。公开题单没有提供动画、函数签名和完整规则。本页因此只训练规格推断方法，不声称描述原变体的具体规则。

来源：[牛客 AI Coding 公开题单](https://aicoding.nowcoder.com/questionlist)。

## 训练题目

拿到一个带动画示例和测试骨架的前端仓库。先从给定轨迹归纳移动、压缩、合并、得分和新方块生成规则，再补齐核心纯函数。最终提交需要列出推断依据、仍未确定的情况和测试证据。

## 建立观察账本

每段动画记录操作前棋盘、方向、操作后棋盘、得分变化和新方块位置。事实只写“发生了什么”，不要在事实列写“因为相同数字合并”。同一观察可能支持多条规则，必须用后续用例区分。

::: tip Prompt 01｜从视频提取事实
```text
下面是我逐帧记录的输入棋盘、方向和输出棋盘。
请只整理可直接观察的事实，并列出互相竞争的最小规则假设。
不要使用标准 2048 的先验补齐缺失帧，也不要写实现。
```
:::

## 把二维移动缩成单行变换

四个方向最好归一化为“取一行—按统一方向处理—写回”。核心单行过程可拆为去空、识别可合并组、合并、补空。这里的“识别可合并组”必须来自变体证据，不能默认一个方块每步只合并一次。

::: tip Prompt 02｜规则决策表
```text
请为长度为 4 的单行输入构造决策表。
覆盖空格、两项、三项和四项可关联数字，并标出哪些输出能区分当前两个候选合并规则。
只给测试输入、各假设预测和需要观察的结果。
```
:::

## 用不变量排除“看起来能跑”的实现

移动前后非零方块的数值关系、得分增量、棋盘尺寸和新方块数量应满足题目规则。若移动没有改变棋盘，就不应生成新方块。动画层不能决定领域结果，否则不同帧率可能改变游戏状态。

::: tip Prompt 03｜不变量清单
```text
根据已确认规则，生成每次 move 前后必须成立的不变量。
区分纯移动、发生合并、无效移动和棋盘满四种情况。
每条不变量说明能抓住哪类 AI 生成错误，不提供函数代码。
```
:::

## 随机生成与核心逻辑分离

核心移动函数应对相同棋盘和方向给出相同结果；新方块位置和值由可注入随机源决定。测试固定随机序列，并分别验证“是否应该生成”与“生成在哪里”。

::: tip Prompt 04｜确定性接口
```text
请把移动计算、得分计算、可移动性判断和新方块生成划分成纯逻辑与随机副作用。
给出依赖方向和测试替身需求，不生成实现。
若函数签名不足以隔离随机性，请明确指出接口风险。
```
:::

## 变形测试弥补样例不足

若规则对左右对称，镜像棋盘后向左移动应与原棋盘向右移动镜像一致；上下方向可通过转置关联。还可以验证无效移动幂等。变形关系必须由已确认规则支持，不能盲目套用。

::: tip Prompt 05｜变形关系审查
```text
请从镜像、转置、重复无效移动和分数守恒中筛选可用的变形测试。
每条先写成立所需前提，再给一个能使错误实现失败的最小棋盘。
不确定对称性时不要擅自采用。
```
:::

## 验收产物

- 动画观察账本与规则版本。
- 至少一个推翻初始假设的反例。
- 单行决策表与方向归一化说明。
- 纯逻辑、随机源和渲染层边界。
- 样例测试、不变量测试和变形测试结果。

::: tip Prompt 06｜规格复盘
```text
请按“观察事实—候选规则—区分实验—确认规则—实现边界—验证证据”整理复盘。
所有无法从动画确认的行为保留为 UNKNOWN，禁止改写成肯定句。
```
:::

## 面试复述

重点不是背出变体规则，而是展示如何从不完整规格中建立证据。说明一个 AI 因标准 2048 先验给出的错误假设，以及你用哪组最小棋盘把它推翻。
