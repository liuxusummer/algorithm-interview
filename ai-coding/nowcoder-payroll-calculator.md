# 薪资计算器

<div class="ai-trend-callout">
  <strong>训练重点</strong>
  <p>这不是把公式翻成若干行运算。候选人要把年度累计状态、计税顺序、金额舍入和政策版本写成可审计规则，并能指出 AI 在边界税率和浮点金额上的常见错误。</p>
</div>

## 资料边界

牛客公开卡片描述了一个月度薪资核算模块，包含社保扣除、累计预扣个税和加班费。完整税率表、舍入规则及输入输出接口未公开。本页只保留这些公开考点，规则参数和验收过程由本站重新设计，不声称复原完整原题，也不提供财税建议。

来源：[牛客 AI Coding 公开题单](https://aicoding.nowcoder.com/questionlist)。

## 训练题目

接手一个已有薪资模块，为单个员工计算某月应发、社保、累计应纳税所得额、本月个税与实发工资。输入还包含本年度前几个月累计收入、累计扣除和累计已缴税额。所有规则都由测试夹具或配置给出，输出必须能解释每一步来源。

## 先画计算流水线

推荐先固定阶段：基础工资与加班费形成应发；应用社保和其他扣除；更新年度累计收入与累计扣除；根据累计税率表算累计应纳税额；减去累计已缴得到本月税额；最后得到实发。任何一步顺序变化都会影响结果。

::: tip Prompt 01｜规则事实表
```text
请把需求整理成有序计算流水线。
每一步列输入字段、输出字段、使用的规则版本、舍入时机和可能需要上月累计状态的地方。
未知税率或扣除口径标记 UNKNOWN，不要用现实政策自行补全。
```
:::

## 金额和比例不能随意用二进制浮点

内部可以统一使用最小货币单位整数，或明确精度与舍入模式的十进制定点数。舍入必须发生在题目规定的位置；“每项先舍入”与“总额最后舍入”可能不同。AI 若混用浮点、整数分和格式化字符串，结果很难审计。

::: tip Prompt 02｜精度审查
```text
这是金额字段、比例字段和当前舍入规则。
请追踪每一步的数值类型与舍入点，构造一个会让二进制浮点或过早舍入产生一分钱差异的最小案例。
不要修改规则，只指出风险和验证方法。
```
:::

## 累计预扣是有状态计算

本月个税不是只用本月工资计算。接口必须明确接收之前的累计值，或从受控仓库读取；同一个月重复计算时还要避免把累计值重复叠加。训练时应区分“纯计算函数”和“保存月度结果”两个动作。

::: tip Prompt 03｜状态与幂等
```text
请画出纯计算、读取累计、保存月度结果三者的边界。
针对同一员工同一月份重复提交、补发工资、撤销后重算、跨年一月四种情况，说明需要什么幂等键和状态检查。
不要把数据库写入藏进计算函数。
```
:::

## 税率边界要用金样测试

每个分段阈值至少测“少一分、刚好、加一分”。同时测零收入、负调整、累计已缴大于新算税额、社保封顶以及跨年清零。预期结果最好由人工表格独立计算，不能让同一个 AI 同时写实现和预期值。

::: tip Prompt 04｜边界金样
```text
根据给定税率表生成边界测试清单。
每个阈值覆盖 threshold-1、threshold、threshold+1，并说明预期落在哪一档。
只生成输入结构和人工推导步骤，不生成实现，也不要让预期值复用被测公式。
```
:::

## 输出要能解释

最终结果不应只有一个实发数字。至少保留应发构成、扣除构成、累计应纳税所得额、适用档位、累计税额、累计已缴与本月税额。解释字段能帮助定位规则错误，也让面试官看到你没有盲信 AI。

::: tip Prompt 05｜可解释结果审查
```text
请审查当前结果对象是否足以回答“为什么本月实发是这个数”。
列出必须保留的中间字段、字段来源和彼此应满足的不变量。
如果某字段可能泄露敏感薪资信息，同时给出日志脱敏建议。
```
:::

## 验收协议

- 同一输入重复计算结果完全一致。
- 分段阈值两侧结果连续且档位正确。
- 各组成项满足“应发－扣除－税额＝实发”。
- 重新加载配置后旧月份仍能按旧规则解释。
- 非法负数、缺失累计和月份乱序得到明确错误。

::: tip Prompt 06｜交付前反方审查
```text
从财务审计、并发重算和规则升级三个角度攻击当前方案。
重点检查浮点误差、累计重复、月份乱序、配置漂移、日志泄露和无法追溯的中间值。
每个风险给一个可重复验证动作，不写成品代码。
```
:::

## 面试复述

先说明自己把公式题重构成“规则版本＋纯计算＋有状态落库＋可解释结果”。重点讲一次 AI 给出的错误舍入或重复累计建议，以及你如何用边界金样和账务不变量将它证伪。
