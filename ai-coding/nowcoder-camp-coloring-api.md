# 阵营涂色 API 服务

<div class="ai-trend-callout">
  <strong>训练重点</strong>
  <p>观察式题面要求从样例推断棋盘规则。先建立规则证据，再定义 HTTP 命令和状态原子性；不要让 AI 同时猜规则、设计接口并生成实现，否则任何测试失败都无法定位。</p>
</div>

## 资料边界

公开卡片说明需要根据观察到的棋盘规则，实现支持阵营投放、移动、吞并的 HTTP API，涉及状态机、模拟与并查集。棋盘尺寸、邻接方式和吞并条件未公开。本页只训练推断与交付过程，不声称给出原题规则。

来源：[牛客 AI Coding 公开题单](https://aicoding.nowcoder.com/questionlist)。

## 训练题目

拿到若干输入输出轨迹和一个 API 骨架。先推断投放、移动、连通和吞并的行为，再实现单步命令、批量命令和状态查询。所有失败命令不得留下部分修改，输出能解释每一步改变的格子与阵营。

## 规则证据与接口设计分开

先维护观察表：前态、命令、后态、直接事实、候选规则。只有规则通过区分样例后，才能进入领域层契约。不要用 HTTP 返回结果反向掩盖尚未确定的棋盘语义。

::: tip Prompt 01｜观察账本
```text
下面是若干前态、命令和后态。
请只提取事实，并为投放、移动、连通、吞并分别列候选规则。
每条规则给一个能与竞争假设区分的最小实验；未知项保持 UNKNOWN。
```
:::

## 状态转换必须原子

移动可能同时改变起点、终点、多个连通分量和阵营归属。先在临时状态上验证全部前置条件，成功后一次提交；失败时棋盘版本不变。若使用并查集，还要考虑删除或移动会破坏连通，普通并查集未必支持。

::: tip Prompt 02｜数据结构质询
```text
请审查“用并查集维护所有连通关系”的建议。
列出哪些命令只会增加连通，哪些可能删除边或拆分分量，以及这对数据结构意味着什么。
在规则未确认前不要给复杂度结论或实现。
```
:::

## HTTP 契约要表达业务失败

区分请求格式错误、越界、非法状态转换、资源冲突和服务内部错误。成功响应包含新版本和变化摘要；批量接口说明是全有全无还是逐项提交。客户端重试有副作用的命令时需要稳定请求 ID。

::: tip Prompt 03｜API 契约
```text
为投放、移动、批量执行和查询定义 HTTP 契约。
列出请求字段、成功结果、业务错误、幂等键、版本冲突和批量原子性。
不选择具体 Web 框架，也不把棋盘规则散落到控制器。
```
:::

## 用性质测试覆盖未知组合

除公开轨迹外，检查棋盘尺寸不变、单格最多一个阵营、非法操作无副作用、同一查询不改状态、变化摘要与前后差异一致。若规则允许守恒，还可验证各阵营格子总数变化。

::: tip Prompt 04｜性质测试
```text
根据已确认规则列出每条命令前后必须满足的不变量。
为投放、移动、吞并和失败命令各给一个最小随机测试策略。
不把尚未确认的对称性或守恒性写成事实。
```
:::

## 批量回放必须可定位失败

批量命令要记录序号、前置版本、结果和失败原因。全有全无模式在任一步失败时回滚；逐项模式则必须说明后续命令基于哪个状态继续。不能只返回“批量失败”。

::: tip Prompt 05｜批量时间线
```text
构造五条命令中第三条失败的批量轨迹。
分别推演原子批量和逐项提交两种契约的最终状态、响应与审计记录。
指出当前题意必须选择哪一种，不能让实现自行决定。
```
:::

## 验收证据

- 每条规则有公开观察或区分实验支撑。
- 非法命令前后状态与版本完全一致。
- 变化摘要可由前后棋盘独立重算。
- 重复请求不会重复投放或移动。
- 批量失败语义与接口文档一致。

::: tip Prompt 06｜反方评审
```text
请寻找当前设计中把假设当事实、用不支持删除的结构处理移动、控制器承载领域规则、失败后部分提交和重试重复执行的问题。
每个问题给最小复现轨迹，不写替代实现。
```
:::

## 面试复述

先讲规格推断，再讲 API。重点解释为什么某次 AI 推荐的并查集方案与“移动可能拆分连通块”冲突，以及你如何通过规则证据和最小轨迹决定是否接受。
