# SaaS 客户续约预测

<div class="ai-trend-callout">
  <strong>训练重点</strong>
  <p>公开卡片特别强调理解数据生成机制。高分不来自堆模型，而来自识别标签发生时间、避免未来信息泄漏、构造可信验证集，并用稳定基线判断复杂方案是否真的泛化。</p>
</div>

## 资料边界

公开题单卡片描述了约 12 万行训练数据、2 万行验证数据和隐藏 holdout，目标是预测 SaaS 客户续约；评价重点偏向数据机制理解。字段、指标和提交格式未公开。本页重建研究流程，不声称拥有完整数据或原题字段。

来源：[牛客 AI Coding 公开题单](https://aicoding.nowcoder.com/questionlist)。

## 训练题目

在限定时间内完成数据审计、验证方案、基线、特征方案和提交说明。模型输出必须可复现；不能把验证集或隐藏集信息带入训练。若使用 AI 分析字段，只能提供字段定义和聚合摘要，不上传未授权客户数据。

## 第一问：一行数据代表什么时刻

先确认观察窗口、预测窗口和标签生成时间。如果某字段是在续约完成后才写入，例如“最终合同金额”或“关闭原因”，它与标签高度相关却无法在线获得。随机切分还可能把同一客户不同月份分到训练和验证两边。

::: tip Prompt 01｜时间语义审计
```text
下面是字段名、类型、缺失率和少量脱敏统计，不包含原始客户记录。
请为每个字段标注“预测时可用、疑似未来信息、身份键、时间键、需要业务确认”。
不能从字段名确定的内容标记 UNKNOWN，不要猜业务语义。
```
:::

## 验证集要模拟隐藏集

若隐藏集来自更晚时间，训练集应按时间向前、验证集向后切分；同一客户还要整体落在一侧。记录时间范围、客户重叠率和标签比例。只有验证机制相似，线下提升才值得相信。

::: tip Prompt 02｜切分方案对抗
```text
请比较随机行切分、按客户分组切分、按时间切分、按客户且按时间切分。
对每种方案说明可能高估或低估什么，并给出验证隐藏集分布假设所需的三项统计。
不要因为某种切分分数更高就推荐它。
```
:::

## 先跑简单基线

建立常数预测、少量稳定字段的线性模型或树模型，并保存训练时间、指标和特征列表。复杂模型只有在相同切分和相同阈值策略下稳定胜过基线才有价值。若指标不明确，要确认是排序指标、概率指标还是固定阈值分类。

::: tip Prompt 03｜基线契约
```text
请为续约预测定义最小基线实验记录。
包含数据版本、切分、预处理、特征、模型、随机种子、评价指标、阈值和运行时间。
只输出实验契约，不生成训练代码，也不把验证集统计用于拟合预处理。
```
:::

## 缺失值可能是业务事件

“没有登录次数”可能表示未接入埋点，也可能表示真实零次；“合同金额缺失”可能只发生在流失客户。先比较缺失率随时间、客户类型和标签的变化，再决定填充。让 AI 直接全列填中位数会抹掉机制信号，也可能泄漏全量统计。

::: tip Prompt 04｜机制假设
```text
针对每个强相关或高缺失字段，生成最多两个数据生成机制假设。
每个假设给一个不接触隐藏标签的验证统计，并说明什么结果会证伪它。
禁止把相关性直接写成因果解释。
```
:::

## 隐藏集稳健性审查

检查类别编码遇到新值、数值超范围、缺列、多列和时间漂移时的行为。训练与预测必须复用同一预处理对象。若排行榜可多次提交，不要围绕一次抖动反复调整；保留本地证据优先。

::: tip Prompt 05｜提交前审查
```text
审查训练到预测的完整数据流。
重点寻找：全量拟合预处理、目标编码泄漏、客户跨集合、未来字段、未知类别崩溃、列顺序依赖和不可复现随机性。
每项只给检测方法和修复边界，不建议盲目增加模型复杂度。
```
:::

## 验收证据

- 数据切分脚本可重复产生相同客户集合。
- 训练统计只从训练折计算。
- 删除疑似泄漏字段后，指标变化有记录和解释。
- 基线、候选模型和消融使用同一验证协议。
- 预测行数、顺序、范围和提交字段通过独立检查。

::: tip Prompt 06｜复盘生成
```text
请把实验记录整理成“数据机制假设—验证统计—保留或拒绝—对隐藏集的影响”。
必须区分事实、推断和仍未知的信息，并列出一个即使分数提升也拒绝采用的泄漏方案。
```
:::

## 面试复述

先讲时间语义和泄漏，再讲模型。最好展示一个“随机切分分数更高，但因客户或未来信息穿越而被主动拒绝”的决定，这比罗列模型名称更能说明 AI Coding 与数据科学能力。
