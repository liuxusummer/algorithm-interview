# 贪吃蛇引擎排错

<div class="ai-trend-callout">
  <strong>训练重点</strong>
  <p>在有缺陷的游戏引擎中，最差策略是让 AI 重写一份贪吃蛇。应先固定可复现轨迹，再分离输入、状态更新、碰撞、增长和渲染，逐个证明到底是哪一步破坏了状态。</p>
</div>

## 资料边界

公开题单卡片说明：候选人需要在存在 Bug 的游戏引擎中实现核心逻辑并修复引擎问题，最终完成贪吃蛇游戏。完整仓库、九宫格规则和交付接口未公开，本页根据该考查形式重新设计训练流程，不声称还原原仓库。

来源：[牛客 AI Coding 公开题单](https://aicoding.nowcoder.com/questionlist)。

## 训练题目

给定一个可运行但行为错误的浏览器游戏仓库。键盘输入、定时器、状态容器、碰撞判定和渲染已经部分存在。要求在不更换框架、不重写渲染层的前提下，修复核心移动逻辑并补齐开始、暂停、结束与重新开始流程。

## 先建立可重放基线

记录初始蛇身、食物位置和按键序列，例如“右、右、下、左”。关闭真实随机数和不稳定计时，使用固定种子或注入的食物序列。只有相同输入能产生相同轨迹，后续的修复证据才可信。

::: tip Prompt 01｜仓库地图与复现
```text
你只能阅读我给出的目录、入口、状态结构和失败轨迹，暂时不要改代码。
请标出输入事件、tick 驱动、状态更新、碰撞、食物生成和渲染分别位于哪里。
把第一个错误帧前后的状态做成差异表，并列出最多三个可证伪假设。
```
:::

## 把每个 tick 拆成有序步骤

典型顺序是读取已确认方向、计算新头、判断边界和自身碰撞、判断是否吃到食物、决定是否移除尾部、提交新状态、生成食物、渲染。顺序不是装饰：移动到旧尾巴的位置在“不增长”时可能合法，在“本次增长”时则不同。

::: tip Prompt 02｜单步状态表
```text
根据当前规则，把一个 tick 拆成严格有序的状态转换。
每一步列读集合、写集合和失败时是否应提交部分状态。
特别分析“新头等于旧尾”“同一 tick 吃到食物”“撞墙与得分同时发生”三种冲突。
```
:::

## 输入队列不能直接修改蛇身

按键事件只负责提出下一方向。需要拒绝立即反向，也要定义一帧内连续两次按键如何处理。若事件处理器直接移动蛇，计时器也移动一次，就会产生难以复现的双步错误。

::: tip Prompt 03｜输入时序审查
```text
下面是 tick 间隔和按键日志。
请判断每次按键应在第几个 tick 生效，哪些反向输入必须拒绝，以及连续输入需要一个槽位还是队列。
用时间线说明，不写事件处理代码。
```
:::

## 随机食物需要可控且不能落在蛇身上

食物生成器应接收当前空格集合或至少循环验证；棋盘已满时进入完成状态，不能无限重试。测试中注入确定性生成器，避免 AI 生成的用例偶尔绿、偶尔红。

::: tip Prompt 04｜随机性隔离
```text
请为食物生成定义依赖接口和不变量。
覆盖普通生成、命中蛇身后重试、只剩一个空格、棋盘已满和固定种子回放。
不要建议在测试里反复运行直到通过。
```
:::

## 引擎 Bug 和业务 Bug 要分开

若暂停后仍有多个定时器运行，这是生命周期缺陷；若转弯后撞到自身，是领域逻辑缺陷。两类修改要分成独立 diff 并分别验证。不要因为一个测试失败就替换状态管理或渲染框架。

::: tip Prompt 05｜最小修改评审
```text
这是失败轨迹、根因证据和计划修改的文件。
请审查修改是否越过职责边界，是否会创建重复定时器，是否把游戏规则塞进渲染层。
只给最小修改范围和回归风险，不提出框架迁移。
```
:::

## 验收轨迹

- 直行、转弯、暂停后恢复。
- 拒绝立即反向和一帧内冲突输入。
- 吃食物后只增长一格、分数只增加一次。
- 撞墙、自撞后停止，重新开始清理旧定时器。
- 食物不落在蛇身上，满盘不会死循环。

::: tip Prompt 06｜交付复盘
```text
请按“复现—假设—观察—根因—最小修复—回归轨迹”整理复盘。
必须指出一处 AI 初始建议为何不可信，以及哪个确定性回放证据最终支持当前结论。
```
:::

## 面试复述

重点讲 tick 时序和确定性回放，而不是展示游戏画面。面试官更关心你能否在陌生仓库中保留既有结构、缩小根因并证明修复不会产生双定时器或随机测试漂移。
