## 题目

现在有一个数据流，元素会逐个到达。你事先不知道数据流一共有多少个元素，也不能回退或重新遍历。

给定正整数 `k`，请只遍历数据流一次，从全部 `n` 个元素中无放回地抽取 `k` 个，使每个元素最终被选中的概率都恰好为 `k / n`。

可以假设数据流至少包含 `k` 个元素。

### 接口约定

```python
reservoirSample(stream, k, rng=None) -> list[int]
```

- `stream` 可以是列表，也可以是只能消费一次的迭代器；
- `k` 是需要保留的样本数；
- `rng` 是可选的随机数生成器，便于使用固定种子测试；
- 返回样本的顺序不作要求。

### 数据范围

- `1 <= k <= n`；
- `1 <= n <= 10^7`；
- 只能顺序读取数据流一次；
- 除返回结果外，只允许使用 `O(k)` 额外空间。

## 示例

```text
输入：stream = [10, 20, 30, 40, 50], k = 2
输出：[20, 50]
```

输出只是一次可能的随机结果。对任意一个输入元素，经过大量独立实验后，它出现在结果中的概率应趋近于 `2 / 5`。

## 为什么不能先知道 n 再随机下标

如果输入是普通数组，可以先得到长度，再随机选择 `k` 个下标。但本题中的输入可能是：

- 持续到达的日志流；
- 无法回退的网络数据；
- 大到不能完整放入内存的文件；
- 结束前无法知道总长度的迭代器。

因此不能保存全部元素，也不能依赖 `len(stream)`。真正的难点是：当后续元素到达时，如何让早到和晚到的元素保持完全相同的入选概率。

## 蓄水池抽样

维护一个容量为 `k` 的蓄水池：

1. 前 `k` 个元素直接放入蓄水池；
2. 处理第 `i` 个元素时，`i` 从 1 开始计数；
3. 在 `[1, i]` 中等概率生成一个整数 `j`；
4. 如果 `j <= k`，就用当前元素替换蓄水池中的第 `j` 个位置；否则丢弃当前元素。

代码中使用 0-based 下标，所以会在 `[0, index]` 中生成随机下标；当随机下标小于 `k` 时执行替换。

## Python 实现

```python
import random
from collections.abc import Iterable


class Solution:
    def reservoirSample(
        self,
        stream: Iterable[int],
        k: int,
        rng: random.Random | None = None,
    ) -> list[int]:
        if k <= 0:
            raise ValueError("k 必须是正整数")

        random_source = rng if rng is not None else random
        reservoir: list[int] = []

        for index, value in enumerate(stream):
            if index < k:
                # 前 k 个元素先把蓄水池填满。
                reservoir.append(value)
                continue

            # 当前是第 index + 1 个元素。
            # 每个历史位置和当前元素获得相同的一次抽签机会。
            selected = random_source.randrange(index + 1)
            if selected < k:
                reservoir[selected] = value

        if len(reservoir) < k:
            raise ValueError("数据流中的元素少于 k 个")

        return reservoir
```

## 正确性说明

下面证明：处理完前 `i` 个元素后，其中每个元素留在蓄水池中的概率都是 `k / i`。

### 基础情况

处理完前 `k` 个元素时，它们全部在蓄水池中，每个元素的入选概率为：

```text
1 = k / k
```

结论成立。

### 加入第 i 个元素

假设处理完前 `i - 1` 个元素后，每个旧元素留在蓄水池中的概率都是 `k / (i - 1)`。

对于新到达的第 `i` 个元素，随机下标落在前 `k` 个位置的概率为：

```text
k / i
```

所以新元素的入选概率正确。

对于任意一个旧元素：

1. 它此前在蓄水池中的概率是 `k / (i - 1)`；
2. 本轮恰好替换它所在槽位的概率是 `1 / i`；
3. 它本轮不被替换的概率是 `(i - 1) / i`。

因此它处理完本轮后仍在蓄水池中的概率为：

```text
k / (i - 1) × (i - 1) / i = k / i
```

新旧元素的入选概率相同。根据数学归纳法，处理完全部 `n` 个元素后，每个元素最终被选中的概率都是 `k / n`。

## 复杂度

- 每个元素只处理一次，时间复杂度为 `O(n)`；
- 蓄水池最多保存 `k` 个元素，额外空间复杂度为 `O(k)`；
- 算法不需要知道 `n`，也不需要保存完整数据流。

## 边界用例

| 场景 | 预期 |
|---|---|
| `k = 1` | 每个元素最终被选中的概率为 `1 / n` |
| `k = n` | 返回全部元素，不发生有效丢弃 |
| 数据流长度小于 `k` | 抛出 `ValueError` |
| `k <= 0` | 抛出 `ValueError` |
| 输入是生成器 | 只消费一次，不调用 `len`，不回退 |
| 包含重复值 | 按元素出现位置抽样；相同值仍代表不同样本 |

## 如何测试随机算法

随机测试不能代替正确性证明，但可以帮助发现明显实现错误：

1. 使用固定种子，让测试可复现；
2. 对小规模输入重复采样数万次；
3. 统计每个位置进入结果的次数；
4. 检查频率是否都接近期望值 `实验次数 × k / n`。

不要要求每个计数完全相等。随机实验天然存在波动，测试应设置合理误差范围。

## 60～90 秒口述稿

输入是未知长度、不可回退的数据流，所以不能先得到总长度再随机下标。我维护一个大小为 `k` 的蓄水池，前 `k` 个元素直接放入。处理第 `i` 个元素时，在 `1` 到 `i` 中等概率抽一个位置；如果落在前 `k` 个位置，就替换对应槽位，否则丢弃。

证明用归纳法。新元素以 `k / i` 的概率进入蓄水池；任意旧元素上一轮被保留的概率是 `k / (i - 1)`，本轮不被替换的概率是 `(i - 1) / i`，相乘也是 `k / i`。所以处理完 `n` 个元素后，每个元素的入选概率都是 `k / n`。

算法单遍扫描，时间 `O(n)`，只保存 `k` 个样本，空间 `O(k)`。

## 常见追问

### 1. 如果只抽一个元素呢？

令 `k = 1` 即可。处理第 `i` 个元素时，以 `1 / i` 的概率用它替换当前样本。

### 2. 如果数据流少于 k 个元素呢？

题目通常保证 `n >= k`。工程接口最好显式检查，本实现会在数据流结束后抛出异常。

### 3. 多台机器上的数据流怎样抽样？

可以先让每台机器记录本地元素数量并完成本地抽样，再根据各分片大小做带权合并。不能简单地从每台机器的样本中等概率再抽一次，因为各分片的数据量可能不同。
