## 题目

给定整数数组 `nums`，返回最长严格递增子序列的长度。

子序列可以删除任意元素，但不能改变剩余元素的相对顺序。本页难度按提供的面试题截图记录。

### 示例

```text
输入：nums = [10, 9, 2, 5, 3, 7, 101, 18]
输出：4
解释：例如 [2, 3, 7, 101]
```

## 解法一：基础动态规划

可以定义 `dp[i]` 为以 `nums[i]` 结尾的最长递增子序列长度，再枚举此前所有更小元素：

```text
dp[i] = max(dp[j] + 1)，其中 j < i 且 nums[j] < nums[i]
```

时间复杂度为 `O(n²)`。进一步观察：相同长度的递增子序列，结尾越小，越容易接上后续元素。

### Python 实现

```python
from typing import List


class Solution:
    def lengthOfLIS(self, nums: List[int]) -> int:
        # 题目保证 nums 至少包含一个元素，所以初始答案为 1。
        ans = 1

        # dp[i] 表示以 nums[i] 结尾的最长严格递增子序列长度。
        # 每个元素单独都能构成长度为 1 的子序列。
        dp = [1] * len(nums)

        for i in range(1, len(nums)):
            # 枚举 i 之前的所有位置，寻找能够接到 nums[i] 前面的元素。
            for j in range(i):
                if nums[i] > nums[j]:
                    # 把 nums[i] 接在以 nums[j] 结尾的序列后面。
                    dp[i] = max(dp[i], dp[j] + 1)

                    # dp[i] 确定了一个更长方案时，同步更新全局答案。
                    ans = max(dp[i], ans)

        return ans
```

### 状态为什么必须表示“以 `nums[i]` 结尾”

如果只定义：

```text
dp[i] = 前 i 个元素中的最长递增子序列长度
```

就不知道这个最长序列最后一个元素是多少，也无法判断 `nums[i]` 能不能接在它后面。

定义为：

```text
dp[i] = 以 nums[i] 结尾的最长递增子序列长度
```

后，转移条件就很明确：只要 `j < i` 且 `nums[j] < nums[i]`，就可以把 `nums[i]` 接到以 `nums[j]` 结尾的序列后面。

### 逐步演算

以：

```text
nums = [10, 9, 2, 5, 3, 7]
```

为例：

| `i` | 当前值 | 可以接在谁后面 | `dp[i]` |
|---:|---:|---|---:|
| 0 | 10 | 无 | 1 |
| 1 | 9 | 无 | 1 |
| 2 | 2 | 无 | 1 |
| 3 | 5 | 2 | 2 |
| 4 | 3 | 2 | 2 |
| 5 | 7 | 2、5、3 | 3 |

处理到 `7` 时，可以从以 `5` 或 `3` 结尾的长度 2 序列转移，因此：

```text
dp[5] = 3
```

注意 `dp[i]` 只表示必须以 `nums[i]` 结尾的答案，整个数组的答案是所有 `dp[i]` 的最大值，所以代码使用 `ans` 持续维护全局最大值。

### 正确性说明

对于每个位置 `i`，任何以 `nums[i]` 结尾、长度大于 1 的严格递增子序列，其倒数第二个元素一定来自某个 `j < i`，并满足 `nums[j] < nums[i]`。代码枚举了所有这样的 `j`，取 `dp[j] + 1` 的最大值，因此不会遗漏任何以 `nums[i]` 结尾的最优方案。所有递增子序列都必然结束在某个位置，故全部 `dp[i]` 的最大值就是整个数组的最长递增子序列长度。

### 复杂度

- 时间复杂度：`O(n²)`，每个位置都枚举此前所有位置。
- 空间复杂度：`O(n)`，用于保存动态规划数组。

## 解法二：最小结尾值 + 二分查找

对于长度相同的递增子序列，结尾值越小，越容易接上后续数字。因此维护数组 `tails`：

```text
tails[length - 1]
= 长度为 length 的递增子序列能够取得的最小结尾值
```

处理新数字 `number` 时，在 `tails` 中二分查找第一个大于等于它的位置：

- 找不到，说明它比所有结尾都大，可以把最长长度增加 1；
- 找到，就用它替换该位置，让这个长度的序列拥有更小或相同的结尾；
- 严格递增要求使用“第一个 `>= number`”的位置，重复值只能替换，不能扩展长度。

### Python 实现

```python
class Solution:
    def lengthOfLIS(self, nums: list[int]) -> int:
        tails: list[int] = []

        for number in nums:
            left = 0
            right = len(tails)

            # 寻找第一个大于等于 number 的最小结尾值。
            while left < right:
                middle = left + (right - left) // 2

                if tails[middle] < number:
                    left = middle + 1
                else:
                    right = middle

            if left == len(tails):
                # number 大于所有最小结尾，可扩展出更长的递增子序列。
                tails.append(number)
            else:
                # 长度不变，但更小的结尾能为后续元素留下更多空间。
                tails[left] = number

        return len(tails)
```

### `tails` 为什么不一定是真实子序列

替换某个位置时，`tails` 中不同位置的值可能来自不同的实际子序列，所以不能直接把整个数组当作最终 LIS。但这不影响长度：

- `tails` 每增加一个位置，都确实发现了一条更长的递增子序列；
- 替换只会减小某个长度的结尾，不会让已经存在的长度消失；
- 更小结尾只会增加未来继续扩展的可能性。

因此 `len(tails)` 始终等于当前前缀的最长递增子序列长度。

### 正确性说明

处理每个前缀后，`tails[i]` 是长度为 `i + 1` 的严格递增子序列的最小可能结尾。新数字替换第一个不小于它的位置，保留了更短前缀结尾严格小于它的条件，同时得到该长度下不更差的最小结尾；若所有结尾都小于它，则能合法扩展最长序列。由归纳法，不变量始终成立，最终数组长度就是 LIS 长度。

### 复杂度

- 时间复杂度：`O(n log n)`。每个元素执行一次二分查找。
- 空间复杂度：`O(n)`。最坏严格递增时保存 `n` 个最小结尾值。

## 边界用例

| 输入 | 预期 | 检查点 |
|---|---:|---|
| `[10,9,2,5,3,7,101,18]` | `4` | 基础路径 |
| `[0,1,0,3,2,3]` | `4` | 多个可选前驱 |
| `[7,7,7,7]` | `1` | 严格递增 |
| `[1,2,3,4]` | `4` | 每个位置都可从前驱转移 |
| `[4,3,2,1]` | `1` | 所有状态保持初始值 |

## 90 秒面试表达

“基础 DP 定义 `dp[i]` 为以当前位置结尾的最长长度，需要两层循环。进一步优化时，我维护 `tails[length-1]`，表示该长度递增子序列的最小结尾。每个新数字二分找到第一个大于等于它的位置并替换；如果不存在就追加。严格递增必须用 `lower_bound`，这样重复值不会增加长度。每个元素二分一次，时间 `O(n log n)`。”

## 常见追问

- 基础 DP 还原序列只需记录前驱；二分版本需要同时记录前驱和各长度的末尾下标。
- 如果题目改成最长非递减子序列，转移条件改为 `nums[i] >= nums[j]`。
