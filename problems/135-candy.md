## 题目

有 `n` 个孩子站成一排，数组 `ratings[i]` 表示第 `i` 个孩子的评分。

给每个孩子至少一颗糖；如果一个孩子的评分高于相邻孩子，他获得的糖也必须更多。返回满足条件所需的最少糖果总数。

本页难度按提供的面试题截图记录。

### 示例

```text
输入：ratings = [1, 0, 2]
输出：5
解释：可以分配 [2, 1, 2]
```

```text
输入：ratings = [1, 2, 2]
输出：4
解释：可以分配 [1, 2, 1]
```

## 解法一：双向扫描

### 为什么要从两个方向看

每个孩子可能同时受到左右两个约束：

- 从左向右扫描，保证评分高于左邻居时糖更多；
- 从右向左扫描，保证评分高于右邻居时糖更多。

第一次扫描得到满足左侧约束的最小分配。第二次扫描时，当前糖果数取原值与“右邻居糖果数加一”的最大值，同时满足两侧约束。

### Python 实现

```python
class Solution:
    def candy(self, ratings: list[int]) -> int:
        candies = [1] * len(ratings)

        # 正向保证比左邻评分高的孩子糖果更多。
        for index in range(1, len(ratings)):
            if ratings[index] > ratings[index - 1]:
                candies[index] = candies[index - 1] + 1

        # 反向补齐右邻约束，取 max 保留已满足的左侧约束。
        for index in range(len(ratings) - 2, -1, -1):
            if ratings[index] > ratings[index + 1]:
                candies[index] = max(
                    candies[index],
                    candies[index + 1] + 1,
                )

        return sum(candies)
```

### 为什么第二遍取最大值

第一遍已经建立了左侧约束。第二遍若直接覆盖，可能为了满足右侧而破坏左侧关系。

取最大值意味着只在右侧约束要求更多糖时增加，不减少第一遍已经确定的必要糖果。

评分相等的相邻孩子之间没有大小约束，因此不需要给相同糖果，也不需要递增。

### 正确性说明

左向扫描后，每个评分高于左邻居的孩子都恰好多拿一颗，得到满足所有左侧约束的最小值。右向扫描对评分高于右邻居的孩子施加同样的最小下界，并与已有值取最大，因此最终满足两侧全部约束。每个位置取的是左右约束下界的最大值，任何合法方案都不能给得更少，所以总糖果数最小。

### 复杂度

- 时间复杂度：`O(n)`，两次扫描加一次求和。
- 空间复杂度：`O(n)`，糖果数组。

## 解法二：上升与下降坡度统计

如果只需要糖果总数，不需要恢复每个孩子具体拿多少颗，可以边扫描边统计连续上升、下降坡度的长度。

- 连续上升长度为 `up` 时，新孩子需要 `up + 1` 颗；
- 评分相等时，约束断开，新孩子只需 1 颗，坡度全部清零；
- 连续下降长度变为 `down` 时，延长整个下降序列会增加 `down` 颗糖；
- 若下降长度超过之前的上升长度，原峰顶还必须额外增加 1 颗，才能继续严格高于右侧。

变量 `peak` 记录当前山峰左侧的上升长度，用来判断峰顶原有糖果是否足以覆盖右侧下降坡度。

### Python 实现

```python
class Solution:
    def candy(self, ratings: list[int]) -> int:
        if not ratings:
            return 0

        total = 1
        up = 0
        down = 0
        peak = 0

        for index in range(1, len(ratings)):
            if ratings[index] > ratings[index - 1]:
                # 上升长度为 up 时，当前孩子需要 up + 1 颗。
                up += 1
                peak = up
                down = 0
                total += up + 1
            elif ratings[index] == ratings[index - 1]:
                # 相等评分没有大小约束，重新从 1 颗开始。
                up = 0
                down = 0
                peak = 0
                total += 1
            else:
                up = 0
                down += 1

                # 下降坡度每延长一步，已有下降段都要形成更高的阶梯。
                total += down

                # 右侧下降比左侧上升更长时，峰顶还要再抬高一颗。
                if down > peak:
                    total += 1

        return total
```

### 为什么下降时增加的是 `down`

下降长度从 `down - 1` 延长到 `down` 后，这一段最小糖果形态需要从：

```text
down, ..., 2, 1
```

扩展成：

```text
down + 1, down, ..., 2, 1
```

与此前相比，总糖果恰好增加 `down`。如果下降长度已经超过峰顶左侧的上升长度，峰顶原来的糖果数不够严格高于右邻居，还需额外加一。

### 正确性说明

连续上升段的最小分配只能是 `1, 2, ..., up + 1`；连续下降段对称地需要从峰顶严格递减到 1。算法按坡度长度累计这两类不可再减少的糖果数。山峰同时属于上升段和下降段，`peak` 与 `down` 的比较确保峰顶取两侧约束所需的较大值，而不会重复计算。因此每段山形都满足相邻约束，且没有任何糖果可以继续减少。

### 复杂度

- 时间复杂度：`O(n)`，只扫描评分数组一次。
- 空间复杂度：`O(1)`，只保存坡度长度与总数。

## 边界用例

| 输入 | 预期 | 检查点 |
|---|---:|---|
| `[1]` | `1` | 单个孩子 |
| `[1,0,2]` | `5` | 两侧都更高 |
| `[1,2,2]` | `4` | 相等评分 |
| `[1,2,3,4]` | `10` | 连续上升 |
| `[4,3,2,1]` | `10` | 连续下降 |

## 90 秒面试表达

“基础写法用糖果数组做两次扫描，分别满足左右约束，时间、空间都是 `O(n)`。如果只求总数，我会把评分序列看成上升坡、平台和下降坡：上升时按坡长加糖，平台重新从一颗开始；下降时每延长一步增加当前坡长，若下降比峰顶左侧上升更长，再给峰顶补一颗。这样单次扫描 `O(n)`，额外空间 `O(1)`。”

## 常见追问

- 若题目要求输出每个孩子的糖果数，应使用双向扫描数组；坡度法只维护总数。
- 如果孩子围成一圈，需要额外处理首尾相邻关系。
- 若比较规则变为评分相等也必须糖果相等，约束模型会改变。
