## 题目

给定一个会议时间安排数组 `intervals`，其中 `intervals[i] = [start_i, end_i]` 表示一场会议从 `start_i` 开始，到 `end_i` 结束。

返回安排所有会议至少需要多少间会议室。

如果一场会议恰好在另一场会议开始时结束，这两场会议可以使用同一间会议室。也就是说，可以把会议区间理解成左闭右开区间 `[start, end)`。

### 示例 1

```text
输入：intervals = [[0,30],[5,10],[15,20]]
输出：2
解释：
会议 [0,30] 进行期间，[5,10] 和 [15,20] 都需要另一间会议室。
后两场会议互不重叠，因此两间会议室足够。
```

### 示例 2

```text
输入：intervals = [[7,10],[2,4]]
输出：1
```

## 先把问题换一种说法

题目并不要求给出每场会议具体使用哪间房，只要求会议最拥挤时同时进行了多少场：

> 最少会议室数量 = 任意时刻正在进行的会议数的最大值。

因此，我们只关心两类时间点：

- 开始时间：正在使用的会议室数量加一；
- 结束时间：一间会议室被释放，数量减一。

这就是扫描线思想。

## 为什么要分别排序

把所有开始时间和结束时间拆成两个有序数组：

```text
intervals = [[0,30],[5,10],[15,20]]

starts = [0, 5, 15]
ends   = [10, 20, 30]
```

`start_pointer` 指向下一场将要开始的会议，`end_pointer` 指向下一场将要结束的会议。比较两个指针所指的时间，就能确定时间线上接下来发生的是“开始”还是“结束”。

这两个指针不是常见的左右夹逼，而是在**归并两条有序事件流**。

## 双指针推演

| 下一开始 | 下一结束 | 先发生的事件 | 正在使用 | 历史最多 |
|---:|---:|---|---:|---:|
| 0 | 10 | 0 开始 | 1 | 1 |
| 5 | 10 | 5 开始 | 2 | 2 |
| 15 | 10 | 10 结束 | 1 | 2 |
| 15 | 20 | 15 开始 | 2 | 2 |

第三步处理结束事件时，`start_pointer` 不动。下一轮仍然比较开始时间 `15`，这样即使一个开始事件之前连续结束了多场会议，也能逐一释放对应的会议室。

## Python 实现

```python
class Solution:
    def minMeetingRooms(self, intervals: list[list[int]]) -> int:
        if not intervals:
            return 0

        # 将开始事件和结束事件拆开并分别排序。
        # 两个数组合起来，相当于一条按时间排列的事件流。
        starts = sorted(interval[0] for interval in intervals)
        ends = sorted(interval[1] for interval in intervals)

        start_pointer = 0
        end_pointer = 0
        rooms_in_use = 0
        max_rooms = 0

        while start_pointer < len(intervals):
            if starts[start_pointer] < ends[end_pointer]:
                # 下一件事是会议开始：必须占用一间会议室。
                rooms_in_use += 1
                max_rooms = max(max_rooms, rooms_in_use)
                start_pointer += 1
            else:
                # 结束时间不晚于开始时间，可以先释放并复用会议室。
                # 这里不移动 start_pointer，下一轮继续处理同一开始事件。
                rooms_in_use -= 1
                end_pointer += 1

        return max_rooms
```

## 为什么相等时要先处理结束

判断开始事件的条件必须是：

```python
starts[start_pointer] < ends[end_pointer]
```

当两者相等时，例如 `[1, 5]` 和 `[5, 8]`，前一场会议已经在时刻 `5` 结束，后一场可以直接复用它的房间。因此应先执行释放操作，而不是新增房间。

如果误写成 `<=`，这个边界会被算成两场会议重叠，答案会多一间。

## 为什么要记录最大值

`rooms_in_use` 只表示当前时刻正在使用的会议室数量。随着结束事件发生，它会减小；题目需要的是整个扫描过程中的峰值，所以必须用 `max_rooms` 保存历史最大值。

例如：

```text
[[0,10],[1,9],[20,30]]
```

扫描到前两场会议时需要两间房，扫描到最后一场时只使用一间，但最终答案仍然是 `2`。

## 正确性说明

两个排序数组的指针始终分别指向尚未处理的最早开始事件和最早结束事件：

- 如果下一开始时间早于下一结束时间，此时没有会议室能提前释放，新会议必然使并发数加一；
- 否则，最早结束的会议已在新会议开始前或同时结束，它的房间可以被释放，并发数减一；
- 每次只处理时间线上最早的未处理事件，所以 `rooms_in_use` 始终等于当前时刻正在进行的会议数。

遍历完所有开始事件后，`max_rooms` 就是整条时间线上的最大并发会议数，也就是安排全部会议所需的最少会议室数量。

## 复杂度

- 时间复杂度：`O(n log n)`。分别排序开始时间和结束时间，双指针扫描为 `O(n)`。
- 空间复杂度：`O(n)`。需要保存两个长度为 `n` 的时间数组。

## 边界用例

| 输入 | 预期 | 检查点 |
|---|---:|---|
| `[]` | `0` | 空输入保护 |
| `[[7,10]]` | `1` | 只有一场会议 |
| `[[1,5],[5,8]]` | `1` | 结束与开始相等，可复用房间 |
| `[[0,30],[5,10],[15,20]]` | `2` | 经典重叠场景 |
| `[[1,10],[2,9],[3,8]]` | `3` | 完全嵌套 |
| `[[1,2],[3,4],[5,6]]` | `1` | 全部互不重叠 |

## 常见错误

- 把比较条件写成 `start <= end`，错误地把首尾相接当成重叠；
- 只返回扫描结束时的 `rooms_in_use`，忘记记录历史峰值；
- 处理结束事件时同时移动两个指针，导致连续结束事件没有被完整处理；
- 直接按原始区间顺序扫描，没有先排序事件；
- 把本题与“合并区间”混淆：合并区间返回区间集合，本题计算最大并发数。

## 90 秒面试表达

“最少会议室数就是时间线上同时进行的会议数峰值。我把所有开始时间和结束时间分别排序，用两个指针归并这两条事件流。如果下一开始时间严格早于下一结束时间，说明新会议开始前没有房间释放，当前占用数加一并更新最大值；否则先处理结束事件，释放一间房。相等时也先结束，因为首尾相接的会议可以复用房间。排序是 `O(n log n)`，扫描是 `O(n)`，额外空间是 `O(n)`。”

## 常见追问

- **如何输出具体的房间分配方案？**

  双指针只统计数量；要恢复分配方案，可以把会议按开始时间排序，并用最小堆保存 `(结束时间, 房间编号)`。

- **会议是闭区间，端点相同也算冲突怎么办？**

  把开始判断改成 `starts[start_pointer] <= ends[end_pointer]`。

- **时间范围很小怎么办？**

  可以使用差分数组，在开始位置加一、结束位置减一，再求前缀和最大值。

- **为什么不用最小堆？**

  最小堆适合同时恢复房间分配；如果只求最少数量，两个排序数组加双指针更直接，复杂度同样是 `O(n log n)`。
