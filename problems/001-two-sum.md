## 题目

给定一个整数数组 `nums` 和一个整数目标值 `target`，请找出数组中和为 `target` 的两个整数，并返回它们的下标。

可以假设每组输入只对应一个答案，但同一个元素不能重复使用。下标顺序不限。

### 示例

```text
输入：nums = [2, 7, 11, 15], target = 9
输出：[0, 1]
解释：nums[0] + nums[1] = 2 + 7 = 9
```

### 约束观察

- 数组无序，不能直接使用首尾双指针。
- 题目需要返回原下标，排序会额外增加下标维护成本。
- 数字可能重复、为负数或为零。
- 同一位置不能使用两次。

## 先说暴力解

枚举所有下标对 `(i, j)`，检查 `nums[i] + nums[j] === target`。这个方案直接、正确，但需要检查约 `n² / 2` 个组合，时间复杂度为 `O(n²)`。

## 优化抓手

当遍历到 `nums[i]` 时，需要知道的不是“后面所有数是什么”，而是此前是否见过它的补数：

```text
complement = target - nums[i]
```

用哈希表记录“数值 → 下标”，即可把补数查询从 `O(n)` 降为平均 `O(1)`。

## Python 实现

```python
class Solution:
    def twoSum(self, nums: list[int], target: int) -> list[int]:
        seen: dict[int, int] = {}

        for index, value in enumerate(nums):
            complement = target - value

            if complement in seen:
                return [seen[complement], index]

            seen[value] = index

        return []
```

## 为什么先查再存

如果先把当前元素存入哈希表，当 `target` 恰好是当前值的两倍时，可能错误地把同一元素使用两次。先查补数、再存当前值，保证命中的下标一定来自之前的位置。

## 正确性说明

遍历到下标 `i` 时，哈希表只保存 `i` 之前出现过的元素。如果补数 `target - nums[i]` 已存在，两个不同下标对应元素之和必然为 `target`；如果不存在，把当前元素记录下来供之后使用。由于题目保证恰好有一个答案，遍历到答案中靠后的下标时一定会命中。

## 边界用例

| 输入 | 目标值 | 预期 | 检查点 |
|---|---:|---|---|
| `[2, 7, 11, 15]` | 9 | `[0, 1]` | 基础路径 |
| `[3, 3]` | 6 | `[0, 1]` | 重复值 |
| `[-3, 4, 3, 90]` | 0 | `[0, 2]` | 负数 |

## 90 秒面试表达

“暴力解需要枚举所有元素对，时间复杂度是 `O(n²)`。遍历每个数时，我真正需要查询的是目标值减去当前数是否已经出现。用哈希表保存已经访问过的值及其下标，就能在平均 `O(1)` 时间完成查询。为了避免同一个元素被使用两次，我会先查补数，再记录当前值。整体时间 `O(n)`、额外空间 `O(n)`。”

## 常见追问

- 如果数组已经有序，可以使用双指针，但若仍要返回原下标，需要额外保存下标信息。
- 如果要返回全部不重复数对，需要继续遍历并明确如何去重。
- 如果数据量极大且内存有限，可以考虑排序后双指针，用 `O(n log n)` 时间换取较少额外空间。
