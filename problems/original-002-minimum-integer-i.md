## 题目

给定一个仅由数字组成的字符串 `num` 和一个非负整数 `k`。

每次操作可以交换 `num` 中两个相邻的数字。请在最多执行 `k` 次操作后，返回能够得到的最小数字字符串。

### 约定

- `num` 的长度在操作过程中不变；
- 返回值按字符串表示，允许包含前导零；
- 等长数字字符串的数值大小与字典序大小一致；
- 可以少于 `k` 次交换，也可以不交换。

### 数据范围

- `1 <= len(num) <= 3 × 10^4`；
- `num` 只包含字符 `'0'` 到 `'9'`；
- `num` 的首字符不为 `'0'`；
- `0 <= k <= 10^9`。

## 示例

### 示例 1

```text
输入：num = "4321", k = 4
输出："1342"
```

解释：

```text
4321 → 4312 → 4132 → 1432 → 1342
```

### 示例 2

```text
输入：num = "100", k = 1
输出："010"
```

把第二位的 `0` 向左交换一次即可。结果按字符串返回，因此保留前导零。

### 示例 3

```text
输入：num = "36789", k = 1000
输出："36789"
```

原字符串已经是能够得到的最小结果，多余的交换次数无需使用。

## 暴力方案为什么不够

为了让结果最小，最先确定的高位最重要。一个直观做法是：

1. 在当前未使用的数字中寻找能移动到最前面的最小数字；
2. 通过相邻交换把它移动到最前面；
3. 从原数组中删除它，继续处理剩余数字。

贪心方向是对的，但如果每次都在线性数组中移动和删除元素，单轮可能需要 `O(n)`，总复杂度会达到 `O(n²)`。

真正需要解决的是两个查询：

- 某个数字下一次出现在哪个原始位置；
- 这个位置前面还有多少个未使用数字，也就是把它移到当前首位需要多少次交换。

## 贪心选择

构造答案的每一位时，从数字 `0` 到 `9` 依次尝试：

1. 只查看这个数字当前最靠前的未使用位置；
2. 计算把它移动到剩余序列首位所需的交换次数；
3. 第一个代价不超过 `k` 的数字，就是当前位的最优选择。

为什么只看同一个数字最靠前的位置？

同样的数字放到当前位，对答案的当前前缀没有区别；更靠前的位置移动代价一定不大于后面的相同数字，还会留下更多交换预算，因此后面的出现位置不会更优。

## 如何快速计算移动代价

假设候选数字的原始下标是 `index`。如果它前面已经有 `removed_before` 个数字被选入答案，那么这些数字已经不在当前剩余序列中。

因此候选数字前面仍未使用的数字数量为：

```text
move_cost = index - removed_before
```

这正是把候选数字移动到当前首位需要的相邻交换次数。

使用树状数组记录哪些原始下标已经被取走，可以在 `O(log n)` 时间内完成：

- 查询某个下标之前已经取走了多少个位置；
- 标记一个原始下标已经取走。

每个数字的所有原始下标按顺序存入双端队列，便能在 `O(1)` 时间取得它最靠前的未使用位置。

## Python 实现

```python
from collections import deque


class FenwickTree:
    def __init__(self, size: int) -> None:
        self.tree = [0] * (size + 1)

    def add(self, index: int, delta: int) -> None:
        # 树状数组内部使用 1-based 下标。
        cursor = index + 1
        while cursor < len(self.tree):
            self.tree[cursor] += delta
            cursor += cursor & -cursor

    def prefix_sum(self, end: int) -> int:
        """返回原数组半开区间 [0, end) 的元素和。"""
        total = 0
        cursor = end
        while cursor > 0:
            total += self.tree[cursor]
            cursor -= cursor & -cursor
        return total


class Solution:
    def minInteger(self, num: str, k: int) -> str:
        positions = [deque() for _ in range(10)]
        for index, character in enumerate(num):
            positions[int(character)].append(index)

        removed = FenwickTree(len(num))
        answer: list[str] = []

        for _ in range(len(num)):
            # 高位权重最大，因此每一位都从最小数字开始尝试。
            for digit in range(10):
                if not positions[digit]:
                    continue

                index = positions[digit][0]
                removed_before = removed.prefix_sum(index)

                # 原下标减去前面已取走的数量，就是当前移动代价。
                move_cost = index - removed_before
                if move_cost > k:
                    continue

                k -= move_cost
                answer.append(str(digit))
                positions[digit].popleft()

                # 标记该原始位置已离开剩余序列。
                removed.add(index, 1)
                break

        return "".join(answer)
```

## 正确性说明

下面证明算法返回最多 `k` 次相邻交换能够得到的最小字符串。

### 引理 1：计算出的移动代价正确

候选数字原本位于下标 `index`，它前面共有 `index` 个数字。树状数组查询得到其中已经被选走的 `removed_before` 个位置，这些位置已经不在剩余序列中。

因此候选数字前面恰好还剩 `index - removed_before` 个数字。每跨过一个数字需要一次相邻交换，所以 `move_cost` 就是把它移动到当前首位的最小交换次数。

### 引理 2：同一数字只需考虑最靠前的未使用位置

选择相同数字的不同出现位置会得到相同的当前答案字符。最靠前的位置前方未使用数字不会更多，移动代价不会更大。

因此如果最靠前的位置不可达，后面相同数字也不可达；如果它可达，选择它至少保留同样多的预算，不会比选择后面的位置差。

### 引理 3：每一位选择最小的可达数字是安全的

算法按 `0` 到 `9` 检查，并选择第一个移动代价不超过剩余预算的数字。所有更小数字都不可在当前预算内移动到这一位。

任何合法答案在当前位要么使用算法选择的数字，要么使用更大的数字。若使用更大的数字，它的整体字典序一定更大，后续位置无法弥补高位差异。

### 定理

根据引理 3，算法为答案第一位作出最优选择；扣除实际交换次数并删除该数字后，剩余问题仍是同样形式的子问题。

对每个位置重复这一论证，算法得到的每一段前缀都是当前预算下可达的最小前缀，因此最终字符串是最多 `k` 次相邻交换能够得到的最小字符串。

## 复杂度

令 `n = len(num)`。

- 每个答案位置最多尝试 10 种数字，10 是常数；
- 每次选中数字会执行一次树状数组前缀查询和一次更新，均为 `O(log n)`；
- 每个原始下标只会入队、出队各一次。

因此总时间复杂度为 `O(n log n)`，下标队列、树状数组和答案占用 `O(n)` 空间。

## 边界用例

| 场景 | 预期 |
|---|---|
| `k = 0` | 原样返回 `num` |
| 长度为 1 | 原样返回 |
| 所有数字相同 | 原样返回，交换没有意义 |
| 结果以 `0` 开头 | 保留前导零 |
| `k` 大于排成最小顺序所需次数 | 返回所有数字按升序排列的字符串 |
| 含大量重复数字 | 每个数字始终使用最靠前的未使用位置 |

## 60～90 秒口述稿

这题的目标是最小字典序，所以从高位到低位贪心。构造当前位时，我尝试数字 0 到 9，只要某个数字最靠前的未使用位置能在剩余 `k` 次交换内移到最前面，就立刻选择它。

难点是原数组中的元素会不断被取走，候选位置的实际移动距离会变化。设候选原下标为 `index`，它前面已经取走 `removed_before` 个数字，那么代价就是 `index - removed_before`。我用树状数组维护已取走位置的前缀数量，用 10 个队列保存各数字的原始下标。

每个位置最多检查 10 个数字，每次查询和更新是 `O(log n)`，总复杂度 `O(n log n)`。正确性来自高位优先：当前能到达的最小数字必须放在当前位，否则答案在这一位就已经更大。

## 常见追问

### 1. 为什么不能只用单调栈？

单调栈适合“删除至多 `k` 个数字”，而本题是相邻交换。把远处数字移到前面需要按距离消耗不同次数，必须动态计算剩余序列中的位置。

### 2. 可以使用线段树吗？

可以。线段树同样能维护某个原始区间中还有多少未使用位置，复杂度也是 `O(n log n)`。这里只需要单点更新和前缀和，树状数组更轻量。

### 3. 如果交换任意两个位置都只算一次呢？

移动代价将不再等于中间元素数量，当前贪心和树状数组模型不能直接套用，需要重新分析交换次数与排列状态。
