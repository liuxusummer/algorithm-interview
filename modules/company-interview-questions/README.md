# 大厂面试真题

这里收录算法题之外的技术面试真题。目前包含 **26 道语言无关的后端核心题**，以及经过最近一年资料调研和三轮对抗筛选保留的 **10 道 Agent 开发高频题**。另设 **Agent 核心工程专题**，用 7 个系统章节讲透从 Runtime、工具和上下文到评估、安全、观测与协议协作的生产实践。不追求题海，而是把每道题讲到能理解、能复述、能应对追问。

如果目标岗位是 NLP、LLM 或 Agent 算法工程，建议从独立的
[NLP · LLM · Agent 算法岗专题](../nlp-llm-agent/README.md)开始。它补齐
Transformer、预训练数据、后训练、LoRA/QLoRA、RAG 和推理系统，再与这里
的 Agent 高频题和核心工程章节衔接。

## 一道题会讲到什么程度

每道题采用相同的分层结构：

1. **面试回答**：先给 30～90 秒可以直接组织出来的主干答案；
2. **原理拆解**：解释状态、数据流和设计动机，不只背结论；
3. **具体例子**：用请求链路、SQL、代码或数字演算落地；
4. **方案取舍**：说明适用场景、代价和失败边界；
5. **常见误区**：指出面试中听起来正确、实际不严谨的说法；
6. **追问与回答**：给出二面、三面常见的继续追问；
7. **自测**：离开页面后检验自己是否真的掌握。

页面会把“快速复习”和“第一次学习”放在一起：赶时间时只读“面试回答”和“常见追问”；系统学习时再顺序阅读原理、例子、取舍与自测。

## 来源说明

“大厂真题”来自候选人公开分享的面试记录，不是公司官方题库。同一家公司不同部门、职级和年份差异很大，因此本站遵循以下规则：

- 公开记录能直接看到问题时，才标注公司与岗位；
- 只引用问题，不照搬原帖答案；
- 技术答案重新依据官方文档、RFC 或论文核验；
- 不根据单条面经推算公司频次；
- 无法核对公司归属时，标为“跨面经高频”，不强贴公司标签。

“问题来源”和“答案依据”严格分开：候选人的公开记录只用于证明“问过什么”，不用于证明答案正确；正文的技术结论优先引用标准、官方文档、原始论文或官方工程实践。

## 推荐学习顺序

第一次学习按依赖顺序：

`CQ01 → CQ02 → CQ13 → CQ14 → CQ03 → CQ15 → CQ16 → CQ04 → CQ05 → CQ19 → CQ06 → CQ17 → CQ18 → CQ07 → CQ08 → CQ09 → CQ20 → CQ21 → CQ22 → CQ10 → CQ23 → CQ24 → CQ25 → CQ11 → CQ12 → CQ26`

面试前复习则按故障链路：

`客户端 → 网络 → 应用线程 → 缓存 → 数据库 → 消息队列 → 监控与排障`

准备 Agent 开发岗位时，建议单独按生产链路学习：

`场景判断 → Agent Loop → 工具契约 → 协议边界 → 状态与记忆 → 可靠恢复 → 评估 → 安全 → 多 Agent → 生产架构`

对应题目为：

`AQ01 → AQ02 → AQ03 → AQ04 → AQ05 → AQ06 → AQ07 → AQ08 → AQ09 → AQ10`

如果第一次系统学习，建议先读 [Agent 核心工程专题](./agent-core/README.md)，建立七个技术域的全景图，再回到高频题进行 60～90 秒限时表达和追问训练。

## 三遍学习法

### 第一遍：建立模型

不要背整段答案。先画出页面中的状态图、数据流或请求链路，再用自己的话解释每个箭头为什么存在。

### 第二遍：限时表达

关掉页面，用 30 秒给结论、90 秒展开机制。回答顺序推荐：

```text
一句话结论 → 关键机制 → 一个例子 → 适用边界
```

如果一开口就陷入实现细节，说明还没有提炼出主干。

### 第三遍：接受追问

让自己回答每页的“常见追问”和“自测”。回答时主动说出方案代价，例如：

- 用缓存换性能，要承担一致性与失效问题；
- 用副本换可用性，不等于零数据丢失；
- 用队列削峰，要承担积压、重复和最终一致性；
- 用全局强一致限流换精确，会增加延迟和可用性成本。

## 通关标准

每道题至少做到：

1. 30 秒内给出直接结论，90 秒内完成一轮有层次的展开；
2. 能画出流程、状态变化或关键数据结构；
3. 能用一个具体例子解释因果，而不是重复术语；
4. 能指出至少两个常见错误说法；
5. 能回答页面末尾的追问与自测；
6. 知道答案的适用边界、失败方式和版本范围。
