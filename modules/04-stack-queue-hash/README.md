# 04 · 栈、队列与哈希

这一组数据结构帮助我们保存“之后还要用到的状态”，并把查找、匹配或顺序约束降到可接受复杂度。

这组题的重点不是记住 `append` 和 `pop`，而是判断“栈里究竟保存值、下标、历史状态，还是尚未完成的解析现场”。

## 本模块目标

- 能用栈处理最近未匹配状态；
- 能解释索引栈中的边界与哨兵；
- 能用辅助栈为数据结构增加常数时间查询；
- 能证明双栈队列的均摊复杂度；
- 能区分普通队列、双端队列和优先队列；
- 能识别嵌套结构的栈帧设计。
- 能组合哈希表与双向链表设计常数时间缓存。

## LRU 的职责拆分

| 操作 | 哈希表职责 | 双向链表职责 |
|---|---|---|
| `get` | 按 key 找到结点 | 把命中结点移动到头部 |
| 更新 | 找到已有结点 | 更新后移动到头部 |
| 新增 | 建立 key 到结点映射 | 新结点插入头部 |
| 淘汰 | 删除旧 key | 删除尾部最旧结点 |

两个结构必须始终一一对应。任何新增或淘汰都要同时更新哈希表与链表，否则会出现失效索引或幽灵结点。

## 常见栈类型对照

| 类型 | 栈内元素 | 典型目标 |
|---|---|---|
| 匹配栈 | 字符或符号 | 验证嵌套关系 |
| 索引栈 | 数组或字符串下标 | 计算距离、边界、区间 |
| 单调栈 | 保持单调的候选下标 | 找最近更大或更小元素 |
| 辅助栈 | 历史最值或聚合状态 | 为栈增加额外查询 |
| 解析栈 | 未完成结构的上下文 | 处理表达式或嵌套编码 |

## 均摊复杂度怎么讲

用栈实现队列时，某一次转移可能是 `O(n)`，但每个元素一生只会：

1. 进入输入栈；
2. 转移到输出栈；
3. 从输出栈离开。

因此 `m` 次操作总成本为 `O(m)`，平均每次 `O(1)`。面试中要明确区分“单次最坏”与“均摊”。

## Python 实现检查表

- 弹栈前是否判断为空；
- 栈里保存值还是下标；
- 重复最小值是否正确处理；
- 多位数字是否按十进制累计；
- 转移数据时是否破坏应有顺序；
- 复合数据结构的多个索引是否同步更新；
- 双向链表删除时前后指针是否同时连接；
- `heapq` 是最小堆，最大堆需要转换；
- 复杂度是否包含输出字符串本身。
