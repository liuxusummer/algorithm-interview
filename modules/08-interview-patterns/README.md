# 08 · 综合面试模式

最后一个模块把知识点放回真实面试：在时间有限、需求可能变化的情况下，稳定地产出可运行代码和可理解讲解。

这里也收录不容易被单一数据结构标签概括、但非常考验建模和证明能力的技巧题。

## 本模块目标

- 在写代码前提取真正限制方案的约束；
- 能把数组、概率等问题转换成更熟悉的模型；
- 能给出正确性证明，而不只依赖样例；
- 能区分最坏复杂度、均摊复杂度和期望复杂度；
- 能设计针对不变量的验证方法。

## 约束如何决定方案

### 寻找重复数

| 约束 | 排除或提示 |
|---|---|
| 不允许修改数组 | 排除原地排序、原地标记 |
| `O(1)` 额外空间 | 排除哈希集合 |
| 数值都在 `[1,n]` | 数组值可以安全作为下一跳下标 |
| 只有一个重复值 | 环入口具有唯一语义 |

### Rand10

| 约束 | 推论 |
|---|---|
| Rand7 每个结果等概率 | 两次调用产生 49 个等概率有序状态 |
| 输出必须严格均匀 | 状态数量必须能被 10 整除 |
| 49 不能被 10 整除 | 必须拒绝部分状态或继续回收随机性 |

## 面试表达模板

1. **重述目标**：输入、输出、是否允许修改、复杂度要求；
2. **给出基线**：排序、哈希、直接取模等自然方案为什么不满足；
3. **完成建模**：数组为何是链表，随机调用为何形成等概率网格；
4. **陈述不变量**：快慢指针的位置关系，接受区间的等概率映射；
5. **证明结果**：环入口对应重复值，每个 Rand10 结果对应相同状态数；
6. **报告复杂度**：特别说明概率算法使用期望复杂度；
7. **走边界**：最小环、重复多次、拒绝区间连续命中。

## 验证方式

| 类型 | 推荐验证 |
|---|---|
| 确定性算法 | 与简单但可靠的参考实现做随机对照 |
| 随机算法映射 | 穷举底层等概率状态，检查每个输出映射数量 |
| 随机算法采样 | 大样本统计只能辅助观察，不能替代数学证明 |
